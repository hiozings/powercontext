# 验证样例：午夜记账酒馆

本样例用于按步骤体验作品，并验证 PowerContext 的记忆确实跨会话生效。模型输出不会逐字一致，以下用「预期行为」而不是固定文案描述。

## 0. 初始状态

- 已按 README 启动 Dify 1.18.0、PowerContext 1.2.0，并导入 `dsl/midnight-tavern.yml`。
- 应用环境变量：`POWERCONTEXT_TOKEN` 已填，`TAVERN_SCOPE_KEY=midnight-tavern-v1`。
- 可选：运行 `tavern_demo.py seed` 预置 3 条旧账；如果不 seed，则从空账本开始。
- 建议先 `tavern_demo.py inspect` 记录当前账本条目数，作为基线。

## 1. 第一次到访（新会话 A）

| 步骤 | 输入 | 预期行为 |
| --- | --- | --- |
| A1 | 打开应用分享链接，确认是**新对话** | 应用显示开场白 |
| A2 | `我第一次来，来杯最便宜的。` | 老白按第一次见的态度回应；回答末尾出现「📜 老白的账本」 |
| A3 | 看 Dify **Logs → 本次运行 → 节点详情** | `确保 Scope`、`列出账本`、`检索旧账` 返回 200；`记一笔` 返回 200 |
| A4 | `翻账本。` | 直接列出账本条目（包含本轮写入的记录），不经过模型 |

如果 A2 后账本仍为空，检查 `记一笔` 节点的响应和 `POWERCONTEXT_TOKEN` 是否与容器一致。

## 2. 跨会话记忆（新会话 B）

**关键：点击「新建对话」开新会话，不要只在 A 里继续发消息。**

| 步骤 | 输入 | 预期行为 |
| --- | --- | --- |
| B1 | （新会话）`我回来了。` | 第一轮就出现旧账，例如提到上次点的酒、欠的钱或花生米事件；不是“第一次见” |
| B2 | `翻账本。` | 列出与 A 会话相同的记录；条目数与 `inspect` 输出一致 |
| B3 | `你记得我妹妹吗？` | 账本没有就明确说没记 / 账本上没写，不编造人物 |

## 3. 状态变化（还债）

| 步骤 | 输入 | 预期行为 |
| --- | --- | --- |
| C1 | `上次欠你的二十块，今天还你。` | 老白收账；`记一笔` 写入还款事实 |
| C2 | `翻账本。` | 出现还款记录 |
| C3 | （新会话）`我回来了。` | 老白提到账已清/态度缓和，而不是继续催债 |

## 4. 无结果与异常

| 情况 | 操作 | 预期行为 |
| --- | --- | --- |
| 账本为空 | 新 Scope 下直接问 `你记得我吗？` | 老白说第一次见 / 账本空的，不编造旧事 |
| PowerContext 不可用 | 暂停 `powercontext` 容器后发消息 | 流程报错或给出「账本打不开」类提示，不应假装记得 |
| 模型未配置 | 未填 DeepSeek Key 时运行 | Dify 明确报模型错误，不输出角色内容 |

## 5. 证据采集

1. **Dify 节点日志**：每次运行的 `确保 Scope` / `列出账本` / `检索旧账` / `记一笔` 请求与响应；截图或导出运行记录。
2. **PowerContext 账本**：
   ```bash
   python3 dify/scripts/tavern_demo.py inspect \
     --base-url http://127.0.0.1:8000 \
     --token "$POWERCONTEXT_DEMO_TOKEN"
   ```
   输出应与会话中「翻账本」一致。
3. **两次会话截图**：A 首次到访、B 新会话翻旧账。
4. 可选：30 秒录屏，从 A2 到 B1。

## 6. 恢复初始状态

- 换一间酒馆：在 Dify 应用环境变量把 `TAVERN_SCOPE_KEY` 改为 `midnight-tavern-v2`，重新 Publish；旧 Scope 不再被读取。
- 清空容器数据：停止 Compose，删除 `~/dify/docker/powercontext-data/`，重新启动 PowerContext；再按需 seed。
- 重置后建议重新记录一次 `inspect` 基线，保证 A/B 会话验证从干净状态开始。
