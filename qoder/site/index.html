01痛点

找一段话，
为什么总要花半小时？

不是没有读过，而是读过的东西没有留下可检索的轨迹。

综述期

“我记得有篇论文说过这个限制，但想不起是哪篇、第几页。”

几十篇 PDF 平铺在文件夹里，靠文件名和记忆翻找；真正需要的是一句原话和它的出处。

复习期

“笔记散在四个工具里，关键词又记不准。”

课程笔记、划线和摘录没有统一入口；按标题翻太慢，按关键词搜又要求你记得原文怎么说。

汇报前

“baseline、指标口径、上周的结论，各在一处。”

组会记录、实验日志和论文结论需要临时拼接，拼完还说不清每个数字来自哪里。

关键词检索要求你记得原文怎么说；纯语义检索又常常给不出准确出处。寻章要同时解决“找得到”和“说得清”。

02核心能力

一次检索，三路信号，
一条可核验的出处。

检索不是给出一个“看起来相关”的答案，而是把你带回那句话所在的页面。

seekdb

混合召回

向量负责意思相近，BM25 负责专有名词与精确短语，元数据负责范围。三路候选在一次查询里汇合，而不是各搜一遍再人工对照。

seekdb

出处可核验

每条结果带文档、页码、原文片段与命中信号。点开就能核对，引用格式可以直接复制，不必再翻回 PDF。

PowerContext

研究记忆

研究主题、关注方法、阅读进度与最近检索写入记忆。检索前读取并扩展查询，而不是每次都从零开始猜你要什么。

PowerContext

阅读进度

按主题记录已读与待读，回顾“本周读了什么、还缺哪一块”。笔记与论文进同一索引，组会前不必再翻聊天记录。

03架构与分工

谁负责检索，谁负责记住。

seekdb 存事实——片段、向量、全文索引与元数据；PowerContext 存关于你的上下文——主题、偏好、进度与最近检索。

两个组件在项目里的实际分工
组件负责什么可以核对什么
seekdb 存储切块、向量、全文索引与元数据；一条 SQL 同时完成 HNSW 向量召回、ngram 全文打分与年份过滤，再由服务层融合排序。 运行 qoder/server/verify.py 复现实测结果，或在结果卡片上核对页码与两路信号分数。
PowerContext 保存研究主题、关注方法、阅读进度与最近检索；检索前读取并扩展查询，检索后把命中的页码写回 scope。 记忆区显示 scope 与召回条数；重复检索时可见每条 0.03 的召回加成。
Qoder 需求拆解、检索演示与整站实现、调试，以及通过 Qoder Sites 发布网站。 下方开发记录与随提交材料提供的对话截图。

04验证样例

三分钟，
验证它真的能找到出处。

本页可以直接试交互；换成 qoder/server 启动后，同样的输入会走真实的 seekdb 混合检索与 PowerContext 记忆。

  1. 1

    启动本地服务

    在 qoder/server 运行 python app.py，打开 127.0.0.1:8787。页头出现「seekdb v1.4.0.0 · 12 个片段 · PowerContext 已连接」即表示链路就绪。

  2. 2

    关闭记忆检索切块边界

    关闭「使用研究记忆」，输入「长文档切块边界怎么处理」。前三条为 E p.2、A p.4、A p.3，E p.2 的关键词信号为 1.00。

  3. 3

    打开记忆再查一次

    启用记忆后查询被扩展为 chunk、分块、片段、overlap，E p.1 的关键词信号升到 1.00 并排到第一；E p.2 的关键词信号降到 0.31。

  4. 4

    核对原文与跨会话记忆

    展开任意结果核对页码与引用；再重复一次「组会说的 baseline 是什么」，记忆区会显示召回了上一轮检索记录，三条结果各获得 0.03 加成。

05Qoder 开发记录

这个网站，
怎么拆出来、
做出来、发出去。

从竞赛题目到可访问的网站，主要开发环节都在 Qoder 中完成。

  1. 需求拆解

    把“方向一”收敛成一个可演示的切片

    从文献检索的痛点出发，拆出检索、出处、记忆、展示四条主线；确定先做“输入问题 → 三路召回 → 带页码结果”的主流程，而不是先铺功能清单。

  2. 技术分工

    让 seekdb 与 PowerContext 各管一件事

    seekdb 负责片段存储与混合检索，PowerContext 负责研究画像、阅读进度与检索历史；明确“检索前读记忆、检索后写回”的闭环，避免两个组件重复存同一份数据。

  3. 实现

    先做能操作的检索面板

    在 Qoder 中完成浏览器侧的融合排序、记忆扩展、信号解释、出处抽屉与整站视觉；样例语料按论文、笔记、实验日志三类组织，保留页码与标签。

  4. 接入

    把检索搬到 seekdb 上跑

    用 pylibseekdb 嵌入式实例建表、导入 12 个片段并建立 ngram 全文与 HNSW 向量索引；把两路召回合并成一条 SQL，再接入 PowerContext 的 scope、检索与写回接口。

  5. 调试

    逐个问题对照预期结果

    用四组问题分别跑关闭记忆与开启记忆两遍，写断言脚本核对前三名与记忆加成；据此修正中文二元分词、扩展词权重、召回加成的上限与移动端排版。

  6. 发布

    通过 Qoder Sites 发布

    本地验证交互与接口后，将静态产物发布为公开站点；托管版在浏览器内演示，本地服务运行时同一页面自动切到真实 seekdb 检索，页头标明当前引擎。

完整对话截图与 Qoder 账号 UID 随提交材料提供，用于核对站点归属与开发过程。
