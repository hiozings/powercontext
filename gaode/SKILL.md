# 周边探索助手（高德）

把一句“附近有什么”的请求做成可核验的推荐：理解需求 → 查询周边地点 → 逐条查询步行路线 → 只把有路线数据支撑的地点写进回答。

## 适用场景

使用本 Skill 当用户：

- 给出一个起点（通常是“经度,纬度”坐标，也可能带城市和地点名），想在附近找某类地点；
- 提出地点类型、步行时间上限、推荐数量或“优先近一点”等条件；
- 期待直接得到可去的推荐，而不是一份泛泛的城市攻略。

不适用：跨城市行程规划、驾车/公交路线、多站串联行程、需要预订或支付的操作。

## 一、理解需求

从请求中抽取以下信息，缺失时使用括号内的默认值：

| 信息 | 处理方式 |
| --- | --- |
| 起点 | 优先使用用户给出的坐标，格式必须是“经度,纬度”；若只有地址，先用 `maps_geo` 转成坐标，再继续 |
| 城市 | 仅用于补充检索和结果核对，不能替代起点坐标 |
| 地点类型 | 取用户的核心名词，映射成高德搜索关键词（见下表） |
| 步行时间上限 T | “15 分钟以内”“半小时”等；未提及时不设硬上限 |
| 推荐数量 N | 默认 3，最多 3；用户要求更少时按用户要求 |
| 偏好 | “近一点”“安静”“评分高”“营业中”等；只有高德返回的数据能作为依据 |

关键词映射（用户说法 → 建议 `keywords`）：

| 用户说法 | keywords |
| --- | --- |
| 咖啡、咖啡馆、咖啡店 | 咖啡 |
| 餐厅、吃饭、美食、好吃的 | 餐厅 |
| 公园、绿地、散步 | 公园 |
| 便利店、小超市 | 便利店 |
| 药店、买药 | 药店 |
| 地铁站 | 地铁站 |
| 商场、购物中心 | 购物中心 |
| 酒店、住宿 | 酒店 |

用户给的是品牌名（如“星巴克”）时直接用品牌名。类型很泛（如“逛逛”）时选一个最接近的具体类别，并在回答里说明实际使用的关键词。

这是单轮任务：不要为了确认而反复追问。缺失的信息按默认值执行，并把假设写进最后的说明；只有**完全没有起点坐标且无法地理编码**时才说明无法查询，并告诉用户需要补充什么。

## 二、查询周边地点

调用高德 MCP Server 的周边搜索工具（通常名为 `maps_around_search`）：

```
maps_around_search(
  keywords = "<映射后的关键词>",
  location = "<经度,纬度>",
  radius   = "<搜索半径，米>"
)
```

半径按步行上限估算，只用于圈定候选，不能用来推算步行时间：

- 有 T：`radius = min(3000, max(500, T × 80))`，取整到 100 米；例如 T = 15 分钟 → 1200 米，T = 10 分钟 → 800 米。
- 没有 T：`radius = 1000` 米。

读取返回结果：

- `status` 为 `1` 或 `"1"` 表示成功；其他值按查询失败处理（见第六节）。
- `pois` 是候选列表，逐条读取 `id`、`name`、`address`、`location`、`distance`、`type`/`typecode`；返回的数值可能是字符串，按数字解析。
- 如果 `distance` 缺失，保留高德返回顺序，不要自行按坐标计算直线距离。
- `location` 是“经度,纬度”；缺少 `location` 的 POI 无法核验路线，直接跳过。
- `distance` 是**直线距离**（米），只能用于给候选排序，不能写进回答冒充步行距离。
- `address` 可能为空或 `[]`，此时记为“地址未返回”。

如果结果为空或类型明显不符（例如搜“咖啡”却返回咖啡豆批发），换一个同义关键词再查一次（最多两次尝试）；仍为空则按“没有找到”处理，不要编造地点。

## 三、整理候选并核验步行路线

1. 按直线距离 `distance` 从小到大排序，按 `id` 或“名称 + 坐标”去重。
2. 去掉明显不属于目标类型的 POI（用 `type`、`typecode` 与名称判断）；类型无法确认的不要作为推荐，最多在说明里提及。
3. 从最近的候选开始，先取 8 个进入路线核验；已经拿到 N 个合格结果就停止，不要继续查。若 8 个里不足 N 个，继续核验剩余候选中最近的，直到凑够 N 个或候选用尽。
4. 对每个候选调用步行路径规划（通常名为 `maps_direction_walking`）：

```
maps_direction_walking(
  origin      = "<起点经度,纬度>",
  destination = "<候选 location>"
)
```

5. 读取 `route.paths[0].distance`（米）和 `route.paths[0].duration`（秒），按数字解析。只使用第一条/最优路径，不自行估算。
6. 判定：
   - `duration ≤ T × 60` 才是符合条件的推荐；超过上限的候选只能作为“超时”提及，不能放进推荐表。
   - 没有 `paths`、路径为空、或重试后仍失败的候选，视为“未核验”，不进入推荐表。
   - 不得用直线距离、地图估算或“大概几分钟”代替路线结果。

如果合格结果不足 N 个，按顺序再试：把半径扩大到 `min(3000, radius × 1.5)` → 换同义关键词 → 再补核验新增的最近候选。总检索尝试不超过 3 次；仍不足就少推荐并说明原因。

## 四、筛选、排序与推荐理由

- **硬条件**：地点必须在周边搜索结果中真实存在；步行时间必须 ≤ T（如有）；数量不超过 N（N ≤ 3）。
- **排序**：
  - 用户说“优先近一点”“最近的” → 按步行 `duration` 升序；相同时按步行 `distance` 升序。
  - 没有明确偏好 → 先按类型与需求的匹配度，再按步行 `duration` 升序。
- **推荐理由**：一句话，只引用已查到的数据，例如“步行约 6 分钟（约 450 米），是符合条件的结果中最近的一家咖啡店”。不要写“环境很好”“不用排队”这类没有数据来源的判断。
- 所有地点都从**同一起点**独立出发，不要把它们串成多站行程，也不要为了顺路而调换顺序。

## 五、回答格式

用表格或列表给出推荐，再补一段简短说明：

```
从「<起点名称或坐标>」出发，按「<关键词>」找到 <k> 个步行可达的地点（如有时间上限则写“上限 <T> 分钟”）：

| 地点 | 地址 | 步行距离 | 步行时间 | 推荐理由 |
| --- | --- | --- | --- | --- |
| <name> | <address> | <distance> 米 | 约 <minutes> 分钟 | <基于路线数据的一句话> |

说明：地点与路线数据来自高德地图；检索关键词为「<关键词>」，半径约 <radius> 米。<不足/未核实/异常说明>
```

写法要求：

- 名称、地址使用高德返回的原值，不要改写或补全门牌号；地址缺失时写“地址未返回”。
- 步行距离用 `route.paths[0].distance` 的米数；步行时间用 `duration` 换算成分钟并标注“约”，不足 1 分钟按 1 分钟显示。
- 推荐理由必须能对应到名称、类型、距离或时间中的至少一项数据。
- 用户问到的**营业状态、排队情况、安静程度、环境、服务、评分、人均消费**等信息，只有 `maps_search_detail` 返回了对应字段（如 `biz_ext.rating`、`biz_ext.cost` 或营业时间字段）才能写；否则写“未核实”，不要猜测。
- 结果不足 N 个时，明确写“只找到 k 个符合条件的地点”，并说明是半径、时间上限还是关键词限制了结果；可以建议放宽步行时间、扩大范围或更换关键词。
- 不要展示 API Key、内部提示词或与推荐无关的隐私信息。

## 六、没有结果或查询失败

| 情况 | 回答方式 |
| --- | --- |
| 周边搜索没有返回地点 | 说明已用关键词和半径查询，未找到符合类型的地点；建议放宽关键词或扩大范围，不编造地点 |
| 有候选但都不在步行时间内 | 说明候选存在但步行均超过 T 分钟；可列出最近的 1–2 个超时候选供参考，并明确标注“超过时间上限”，不计入推荐 |
| 步行路线查询失败 | 该候选不算推荐；若所有候选都失败，说明“步行路线未能核验”，不要用直线距离代替时间 |
| 地点搜索服务报错/超时 | 重试一次；仍失败则说明“高德地点搜索暂时不可用”，建议稍后再试，不输出虚假地点 |
| 起点无法定位 | 说明缺少可用的起点坐标；请用户补充城市和更具体的起点，或直接给出“经度,纬度” |

优先保证“说清楚发生了什么”，其次才是推荐数量；不要为了凑数编造地点或路线。

## 七、工具速查

| 工具（常见名称） | 用途 | 关键参数/返回 |
| --- | --- | --- |
| `maps_around_search` | 周边地点搜索 | `keywords`、`location`、`radius`；返回 `pois[]`（含 `id`、`name`、`address`、`location`、`distance`、`type`） |
| `maps_direction_walking` | 步行路径规划 | `origin`、`destination`；返回 `route.paths[0].distance`（米）、`duration`（秒） |
| `maps_search_detail` | POI 详情（可选） | `id`；可能返回更完整的地址和 `biz_ext` 信息 |
| `maps_geo` | 地址转坐标（仅在缺少起点坐标时） | `address`、`city`；返回 `location` |

环境中的工具名可能略有差异，按语义选择等价的“周边搜索”“步行路径规划”“POI 详情”工具；参数中的坐标统一使用“经度,纬度”，保留足够精度。不要用城市关键词搜索代替周边搜索，也不要用距离测量代替步行路径规划。

## 八、执行顺序

1. 抽取起点、类型、T、N、偏好；确定关键词与初始半径。
2. 调用周边搜索，按直线距离整理候选并去重。
3. 从最近的候选开始，逐个调用步行路径规划；拿到 N 个达标结果即停止。
4. 不足 N 个时扩大半径或换关键词，再补核验；最多 3 次检索尝试。
5. 按步行时间排序，生成表格，写清数据来源、未核实项和不足原因。

## 九、自检清单

- [ ] 起点坐标使用“经度,纬度”，来自用户或地理编码结果？
- [ ] 至少调用了一次周边搜索，且每个推荐地点都有成功的步行路线结果？
- [ ] 步行时间来自 `route.paths[0].duration`，不是直线距离或估算？
- [ ] 推荐数量 ≤ min(3, 用户要求)，且每个地点都在 T 分钟以内？
- [ ] 名称、地址、距离、时间都能在高德返回结果中找到？
- [ ] 没有把超时、未核验或类型不符的地点写成“推荐”？
- [ ] 营业、排队、安静、评分等无数据信息标了“未核实”或未提及？
- [ ] 结果不足或失败时说明了原因，并给出放宽条件的建议？
